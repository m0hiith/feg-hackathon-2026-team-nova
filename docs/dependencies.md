# Dependencies and declarations

_Versions below are the ones actually installed and used to produce every
number in `docs/`. Verify with `pip list` in the environment created from the
root `requirements.txt`._

---

## 1. Runtime dependencies

Both halves are **Python 3 standard library plus a small, permissively
licensed set.** There is no ML dependency anywhere: no scikit-learn, no
PyTorch, no TensorFlow, no XGBoost, no LLM API. Both engines are rule-based
(`docs/architecture.md`); there is nothing to train and nothing to serve.

| package | version | licence | used by | role |
|---|---|---|---|---|
| **duckdb** | 1.5.5 | MIT | `detection/src/replay.py`, `detection/src/features.py`, `detection/src/trigger.py`, `detection/scripts/*.py` | Reads the event parquet/CSV and does all set-based aggregation. Detection-only. |
| **pandas** | 3.0.5 | BSD-3-Clause | `detection/scripts/build_ui.py`, `detection/scripts/profile.py`, all of `response/src/*.py`, `response/tools/*.py` | Session/event dataframes throughout `response/`; parquet/profile reads in `detection/`. |
| **pyarrow** | 25.0.1 | Apache-2.0 | transitive (`pandas.read_parquet`) | Parquet engine. |
| **numpy** | 2.5.3 | BSD-3-Clause (0BSD/MIT/Zlib/CC0-1.0 components) | transitive (`pandas`) | — |
| **openpyxl** | ≥3.1 | MIT | `detection/scripts/profile.py`, `response/tools/generate_synthetic_users.py` | `.xlsx` read/write engine for the dataset files. |

Standard library only, everywhere else: `argparse`, `collections`,
`dataclasses`, `datetime`, `enum`, `hashlib`, `importlib`, `json`, `math`,
`pathlib`, `random`, `re`, `sys`, `types`, `typing`, `__future__`.

**Both demo UIs have no runtime dependency at all.** `detection/src/ui/
index.html` and `response/feg-session-engine.html` are each one
self-contained HTML file — no build step, no framework, no external script
call. `response/feg-session-engine.html` uses the Tailwind CSS play-CDN
script (`cdn.tailwindcss.com`) for utility classes and inlines its own Font
Awesome subset (§4) rather than loading it from a CDN.

## 3. Datasets — stated separately, on purpose

**FEG-provided (real), used by `detection/` only:**

| file | rows | what it is |
|---|---|---|
| `top_casino_users_event_logs.csv` | 332,119 | Client-side behavioural event log — the only file `detection/` reads for its trigger and evaluation. |
| `SB_Player.csv`, `SB_MOM.csv`, `EPS_Offers.csv`, `hackathon_casino_trends.xlsx` | — | Used only as context/benchmarks in `detection/docs/DATA_MAP.md` and `docs/impact-case.md` §6 (the median-payin figure); never read by the trigger pipeline itself. |

None of these are committed to this repository — see `.gitignore` and
`docs/compliance-note.md` §1. The delivered CSV is sanitised
(`detection/scripts/sanitize.py`) before any other code reads it: real
`username=`/`temptoken=` credentials found in `page_location`/
`page_referrer` query strings are stripped and their absence is asserted,
on disk, before the derived `data/clean/events.parquet` is written.

**Synthetic (fabricated, never real), used by `response/` only:**

| file | rows | what it is |
|---|---|---|
| `synthetic_player_event_logs.csv` / `.xlsx` | 44,261 events, 8 players, 5,237 sessions | Generated by `response/tools/generate_synthetic_users.py`, seed `20260908`. Every row `is_synthetic=True`, every `PlayerID` prefixed `SYN_Uxx`. |
| `synthetic_user_profiles.csv` | 8 rows | Ground-truth habit profile per synthetic player — a validation target for `response/src/profiler.py`, never an engine input (`profiler.py`'s own docstring: *"`load_ground_truth()` is never imported here"*). |

**Three columns are appended on top of FEG's own 24-column schema and are
disclosed here so no reviewer mistakes them for fields FEG's real export
has:** `stake_eur`, `odds` (both absent from the real event log — FEG's
provided data has no monetary or price field of any kind), and
`is_synthetic` (always `True`). This is why `response/` cannot be built or
validated on FEG's real data: the honest-disclosure and pre-fill logic in
`docs/compliance-note.md` §5 has nothing to operate on without a stake and
an odds field.

Full per-file provenance for the real dataset (row/column profiles, join
feasibility, personal-data findings): `detection/docs/DATA_MAP.md`.

## 4. Font Awesome — the icon subset in `response/feg-session-engine.html`

The mock site inlines a **self-contained subset** of Font Awesome 6 Free —
only the glyphs actually referenced in the page (built by
`response/tools/build_fa_subset.py`, which scans the page's own markup and
runtime-constructed icon names for `fa-*` classes, then emits a minimal CSS
block with the woff2 font faces embedded as base64 `data:` URIs). No CDN call
is made for icons at runtime. The built subset is committed as
`response/tools/fa-inline.css` so `response/tools/build_publish.py` can
rebuild `feg-session-engine.html` from `Image 2.html` without needing network
access or the original Font Awesome kit files.

**Font Awesome Free licensing** (unchanged by subsetting — a subset of a
Free-tier font remains under the same terms):

| component | licence |
|---|---|
| Icons | CC BY 4.0 |
| Fonts | SIL OFL 1.1 |
| Code (CSS) | MIT |

## 5. AI-assisted development — declared

**This project was developed with AI assistance** (Anthropic Claude, used as
a coding assistant inside the editor, and — for this restructuring and
documentation pass — Claude Code). Declared for transparency, per the
hackathon's own disclosure expectation.

What that means in practice, stated honestly:

- AI assistance was used for writing and refactoring code, generating the
  analysis scripts, drafting these documents, and reviewing for consistency,
  in both `detection/` and `response/`.
- **Every number in `docs/` is produced by executing a script in this repo**,
  not written by hand and not generated by a language model from memory.
  Each figure names the command that reproduces it.
- The design decisions — a rule-based engine over a model in both halves,
  silence as a first-class, counted output, a player-level rather than
  session-level train/test split, the `exclude_session` leakage guard,
  refusing to publish a headline euro figure, labelling the taps-to-action
  reduction as a design claim rather than a measurement — are recorded with
  their reasoning in the module docstrings and in `docs/impact-case.md` /
  `docs/compliance-note.md`, not only in this disclosure.
- Two claims carried in earlier drafts of the detection docs were checked
  against the data during that work and corrected rather than left standing
  (`detection/docs/dependencies.md` §4–5): an illustrative price pair was
  swapped for a real `EPS_Offers.csv` row, and an Android telemetry claim
  that had implied a flat coverage rate was re-measured, found partly wrong,
  and restated with per-player evidence.

**No AI model is used at runtime, in either half.** Nothing in `detection/
src` or `response/src` calls a model, and the shipped artefact contains no
inference of any kind.

## 6. Finding carried from the detection half: the Android screen-name gap

Recorded here because it is a data-quality finding that limits the product
and the fix is on FEG's side, not an analysis gap on ours.
`fortuna_screen_name` — the column that names the screen a user is on — is
populated on 100.0% of SB iOS view events, 39.1% of SB Android, 6.9% of
Casino Android, and 0.0% of GM/web (measured over `detection/data/clean/
events.parquet`). This is why `docs/impact-case.md` §2 recommends SB-iOS-only
rollout from the current data, and it is the leading candidate explanation
(alongside a genuine platform difference that cannot be separated from it
with this dataset) for why the detection trigger's lift collapses to at or
below the base rate on GM and SB Android out of sample. Full measurement and
the back-and-forth signal it currently blocks: `detection/docs/
dependencies.md` §5.
