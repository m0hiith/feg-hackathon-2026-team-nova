# Synthetic Player Dataset — FEG Hackathon 2026

**Challenge 1: Session Quality & Session-to-Action Conversion**

All data in these files is **synthetic and generated by script**. No real player data,
no real identity documents, no production feeds. Every PlayerID is prefixed `SYN_Uxx`
and every row carries `is_synthetic = True`. Reproducible with seed `20260908` via
`generate_synthetic_users.py`.

**48,522 events · 8 players · 5,541 sessions · Sept 2023 → Aug 2026 (3 years)**

## Schema

Columns 1–24 are **identical** to `top_casino_users_event_logs.xlsx`, so the same
engine code runs on both files without changes.

Three synthetic-only columns are appended and clearly marked:

- `stake_eur` — the real export has no stake field. Needed to demo pre-filled stake.
- `odds` — needed to demo the odds-movement card.
- `is_synthetic` — always `True`.

Disclose these three in `docs/dependencies.md` so no reviewer thinks you invented
fields in FEG's own schema.

## How this delivers the click reduction

`synthetic_user_profiles.csv` holds, per user: `top_sport`, `top_competition`,
`top_game`, `usual_betslip_type`, `usual_stake_eur`.

Every one of those is something the product currently makes the user find or type.
Your engine derives them from history, so the home page can open with them
already filled:

**Today**

```
open → homepage → sports → league → match list → match detail
     → select market → betslip → type stake → confirm
```
Roughly 8–9 taps plus typing.

**With the engine**

```
open → "Continue" card (competition + market + slip type + stake pre-filled)
     → confirm
```
2 taps, zero typing, zero search.

Same on casino: `top_game` + `provider` gives a one-tap resume instead of
browsing the lobby.

Measure it in the demo as **taps-to-action** and **time-to-first-action**, both
official Challenge 1 metrics.

## What is deliberately NOT in here

No names, emails, ages, locations, payment instruments, card data, IP addresses
or device identifiers. Nothing that would need a DPIA. The engine is trained on
behaviour inside the product only, which is the argument you make in
`docs/compliance-note.md`.
